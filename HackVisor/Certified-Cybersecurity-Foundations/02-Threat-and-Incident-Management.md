\## 1. Cyber Kill Chain



The Cyber Kill Chain is a model used to understand the different

stages of a cyber attack.



The seven stages are:



1\. Reconnaissance

2\. Weaponization

3\. Delivery

4\. Exploitation

5\. Installation

6\. Command and Control (C2)

7\. Actions on Objectives



\### Stage Overview



\*\*1. Reconnaissance\*\*



The attacker gathers information about the target, such as

systems, users, domains, or exposed services.



\*\*2. Weaponization\*\*



The attacker prepares a malicious payload or other resources

to be used against the target.



\*\*3. Delivery\*\*



The attacker delivers the malicious payload to the target.



Examples may include phishing emails, malicious files, or

compromised websites.



\*\*4. Exploitation\*\*



The attacker exploits a vulnerability or weakness in the

target environment.



\*\*5. Installation\*\*



The attacker establishes malware or another mechanism that

allows continued access to the compromised system.



\*\*6. Command and Control (C2)\*\*



The compromised system communicates with infrastructure

controlled by the attacker.



\*\*7. Actions on Objectives\*\*



The attacker performs their intended objective, such as

stealing information, disrupting services, or modifying data.



\---



\## Security Relevance



Understanding the Cyber Kill Chain helps defenders identify

potential attack activity and determine where security controls

and detection mechanisms can be applied.



For example:



| Attack Stage | Defensive Focus |

|---|---|

| Reconnaissance | Monitor unusual scanning and information gathering |

| Delivery | Email and network security controls |

| Exploitation | Vulnerability management and detection |

| Installation | Endpoint monitoring |

| C2 | Network traffic monitoring |

| Actions on Objectives | Data and activity monitoring |



This model can help security analysts understand the possible

progression of an attack and investigate suspicious activity

within the correct context.

\# 2. Incident Response Lifecycle



I learned that incident response follows a structured lifecycle

to help organizations prepare for and respond to cybersecurity

incidents.



The main phases are:



1\. Preparation

2\. Detection and Analysis

3\. Containment

4\. Eradication

5\. Recovery

6\. Post-Incident Activity



\---



\## Preparation



Organizations prepare before an incident occurs.



This can include:



\- Developing incident response plans

\- Preparing security tools

\- Creating response procedures

\- Training security personnel

\- Establishing communication procedures



The goal is to ensure that the organization is prepared to

respond effectively when an incident occurs.



\---



\## Detection and Analysis



Security teams identify and investigate potential security

incidents.



Sources of information may include:



\- Security alerts

\- System logs

\- Network traffic

\- Endpoint activity

\- Indicators of compromise (IOCs)



The objective is to determine whether suspicious activity

represents a security incident and understand its potential

scope and impact.



\---



\## Containment



Containment focuses on limiting the impact of an incident and

preventing further spread.



Possible actions include:



\- Isolating affected systems

\- Blocking malicious network connections

\- Disabling compromised accounts

\- Restricting access to affected resources



\---



\## Eradication



Eradication focuses on removing the cause of the incident.



Possible actions include:



\- Removing malware

\- Removing persistence mechanisms

\- Patching exploited vulnerabilities

\- Removing malicious accounts

\- Eliminating other identified attack components



\---



\## Recovery



Recovery involves restoring affected systems and returning

operations to normal.



Activities may include:



\- Restoring systems

\- Recovering data

\- Validating system functionality

\- Monitoring systems after recovery



\---



\## Post-Incident Activity



After the incident has been resolved, the organization reviews

what happened and identifies lessons learned.



Activities may include:



\- Creating an incident report

\- Performing root cause analysis

\- Reviewing the response process

\- Improving security controls

\- Updating incident response procedures



This phase helps organizations improve their ability to handle

future incidents.



\---



\# 3. Incident Response Playbooks



I also learned about Incident Response Playbooks.



A playbook is a predefined set of procedures that guides

security teams when responding to a specific type of incident.



Examples include:



\- Phishing incidents

\- Malware infections

\- Compromised accounts

\- Data breaches

\- Suspicious network activity



A playbook helps security teams follow a consistent response

process instead of deciding every response action from scratch.

\## SOC Relevance



The concepts from this module are directly relevant to

A SOC analyst may be involved in activities such as:



\- Monitoring security alerts

\- Investigating suspicious activity

\- Analyzing logs

\- Identifying indicators of compromise

\- Determining the scope of an incident

\- Escalating confirmed incidents

Understanding both the attack lifecycle and incident response
